# slopthenews — Implementation Plan

A news aggregation site where AI models ("authors") each write their own article about the
same current event from the same frozen set of RSS sources. Readers react, favorite, comment,
and share. Think of it as a public editorial benchmark.

> **How to use this plan:** Work through the tasks in order. Each task lists the files to
> create, what to build, and how to check it is done ("Done when"). Do not start a task until
> the previous one passes its checks. Do not add features that are not listed.

---

## 0. Fixed Decisions

| Topic | Decision |
|---|---|
| Language | TypeScript (strict), Node 22 |
| Package manager | pnpm workspaces |
| Web | Next.js 15 (App Router, Server Components, Server Actions) |
| Styling | Tailwind CSS v4 + Headless UI (`@headlessui/react`) + `@heroicons/react` |
| Database | PostgreSQL 16 + `pgvector` extension |
| ORM | Drizzle ORM + drizzle-kit |
| Auth | Better Auth, email + password only, `admin` plugin for roles |
| Jobs | pg-boss (runs on the same Postgres) |
| LLM client | `ai` (Vercel AI SDK) + `@ai-sdk/openai-compatible` |
| Validation | Zod |
| Embeddings | `@huggingface/transformers`, model `Xenova/all-MiniLM-L6-v2` (384 dims), runs locally in worker |
| RSS | `rss-parser` |
| Article text | `@mozilla/readability` + `linkedom` |
| Tests | Vitest |
| Deploy | Docker Compose on Dokploy: `postgres`, `web`, `worker` |

**Out of scope for MVP:** blind mode, OAuth, email verification, user profile customization,
regenerating articles when an event gets new sources, search, notifications.

## 3. Database Schema (`packages/db/src/schema.ts`)

All ids are `text` primary keys generated with `crypto.randomUUID()` unless noted.
All tables have `createdAt timestamp default now()`.

### Auth (generated by Better Auth CLI; do not hand-write)
`user` (adds `role text default 'user'`, `banned boolean`), `session`, `account`, `verification`.

### Content
```
provider
  id, name text unique, baseUrl text, apiKeyEncrypted text, enabled bool default true

author
  id, providerId -> provider.id, slug text unique, displayName text, modelId text,
  bio text null, temperature real default 0.7, maxTokens int default 2000,
  enabled bool default true

feed
  id, name text, outlet text, url text unique, enabled bool default true,
  lastFetchedAt timestamp null, lastError text null

raw_article
  id, feedId -> feed.id, outlet text, url text unique, title text, excerpt text,
  content text null, publishedAt timestamp, embedding vector(384) null,
  eventId -> event.id null

event
  id, title text, centroid vector(384), outletCount int default 0,
  status text  -- 'open' | 'queued' | 'generated' | 'skipped'
  firstSeenAt timestamp, lastSeenAt timestamp

source_packet
  id, eventId -> event.id unique, articleIds text[], payload jsonb, contentHash text

prompt_template
  id, version int unique, system text, user text, active bool default false

generation_run
  id, authorId -> author.id, packetId -> source_packet.id, promptVersion int,
  status text  -- 'pending' | 'running' | 'succeeded' | 'failed' | 'invalid'
  latencyMs int null, tokensIn int null, tokensOut int null,
  rawOutput text null, error text null, finishedAt timestamp null
  UNIQUE(authorId, packetId)

post
  id, runId -> generation_run.id unique, eventId -> event.id, authorId -> author.id,
  slug text unique, headline text, dek text, body jsonb, publishedAt timestamp,
  likeCount int default 0, dislikeCount int default 0, commentCount int default 0,
  favoriteCount int default 0, shareCount int default 0,
  citationValidRatio real

post_citation
  postId -> post.id, index int, rawArticleId -> raw_article.id
  PK(postId, index)
```

### Interactions
```
reaction   userId, postId, value smallint (1 = like, -1 = dislike), PK(userId, postId)
favorite   userId, postId, PK(userId, postId)
comment    id, postId, userId, parentId null, body text, hidden bool default false
share      id, postId, userId null, channel text  -- 'copy' | 'x' | 'reddit' | 'email' | 'native'
```

Indexes: `raw_article(publishedAt)`, `raw_article(eventId)`, `event(status, lastSeenAt)`,
`post(eventId)`, `post(authorId)`, `comment(postId)`, HNSW index on `event.centroid`.

## 4. Article Output Contract (`packages/core/src/article-schema.ts`)

Every author must return JSON matching this Zod schema:

```ts
export const ArticleSchema = z.object({
  headline: z.string().min(10).max(140),
  dek: z.string().min(20).max(300),           // one-sentence summary
  sections: z.array(z.object({
    heading: z.string().max(100).optional(),
    paragraphs: z.array(z.object({
      text: z.string().min(1),
      citations: z.array(z.number().int().min(1)).min(1), // source numbers from the packet
    })).min(1),
  })).min(1).max(8),
});
```

### Source packet payload (what every author receives)
```json
{
  "eventTitle": "…",
  "sources": [
    { "n": 1, "outlet": "BBC", "title": "…", "publishedAt": "…", "url": "…", "text": "… (max 1500 chars)" }
  ]
}
```
At most 8 sources per packet, one per outlet first, then newest.

### Validation rules (`packages/core/src/validate.ts`)
1. Output parses as JSON and matches `ArticleSchema`. If it does not, the run status is `invalid`.
2. Every citation number exists in the packet. Bad numbers are removed, and the article is
   `invalid` if fewer than 50% of its citations are valid.
3. `citationValidRatio` = valid citations / total citations.
4. No paragraph may contain 30 or more consecutive words copied from any source. If one does,
   the run is `invalid`.

## 5. Pipeline (apps/worker)

pg-boss queues and the order they run in:

```
pipeline.tick (cron PIPELINE_CRON)
  └─> ingest  ──> cluster ──> select ──> for each selected event: build-packet
                                                  └─> for each enabled author: generate
```

| Job | Input | Does | Output |
|---|---|---|---|
| `pipeline.tick` | — | Sends `ingest`. Exits early if no enabled author exists. | — |
| `ingest` | — | For each enabled feed: parse RSS, insert new `raw_article` rows (skip URLs already stored), try to fetch the page + Readability for `content` (5s timeout, failures are ok), compute embedding of `title + excerpt`. Then send `cluster`. | rows |
| `cluster` | — | For each `raw_article` with `eventId IS NULL`: find nearest `event` with `lastSeenAt` within `CLUSTER_WINDOW_HOURS` and cosine similarity ≥ `CLUSTER_SIMILARITY`. If found: attach, update centroid (running mean), `lastSeenAt`, `outletCount` (distinct outlets). Else: create event with `title = article.title`. Then send `select`. | events |
| `select` | — | Pick events with `status='open'`, `outletCount ≥ MIN_OUTLETS_PER_EVENT`, ordered by `outletCount DESC, lastSeenAt DESC`, limit `EVENTS_PER_RUN`. Set `status='queued'`, send `build-packet` for each. | — |
| `build-packet` | `{eventId}` | Create `source_packet` (skip if exists — **this is the de-dupe**). For each enabled author, insert `generation_run` (pending) and send `generate`. Set event `status='generated'`. | runs |
| `generate` | `{runId}` | Load author + decrypt provider key. Call model via AI SDK `generateText` with the active prompt template; parse JSON from the response (strip code fences). Validate. On success: insert `post` + `post_citation`, `status='succeeded'`. Record latency and tokens either way. Retry limit 2 for network errors only. | post |

Concurrency: `generate` uses `teamSize: 2`. Each job is idempotent: check state before acting.

Note: `generateText` + manual JSON parsing is used instead of `generateObject` because not
every OpenAI-compatible endpoint supports structured output.

### Prompt template v1 (seeded, `packages/db/src/seed.ts`)
- **System:** "You are a news writer. Write one neutral, factual news article that combines the
  provided sources. Use only facts found in the sources. Every paragraph must cite the sources
  it uses by number. Note where sources disagree. Do not copy sentences. Respond with JSON
  only, matching this shape: {schema description}."
- **User:** `Event: {{eventTitle}}\n\nSources:\n{{numbered sources}}`

### Seed feeds (all checked working)
All HTTP requests (RSS and article pages) **must** send the header
`User-Agent: slopthenews/0.1 (+PUBLIC_SITE_URL)`. The Guardian returns 403 to browser-like
user agents. DW serves RSS 1.0 (RDF), which `rss-parser` supports; handle `dc:date` as
the publish date.

## 6. Web Routes (apps/web)

### Public
| Route | Content |
|---|---|
| `/` | Latest events (paginated, 20). Each card shows the event title, number of sources, and one chip per author post linking to it. |
| `/events/[id]` | Event title, Headless UI `TabGroup` with one tab per author post (headline, dek, body, per-post stats), shared source list. |
| `/posts/[slug]` | Full post: author, date, body with superscript citation links `[n]`, sources list, action bar, comments. Includes Open Graph meta. |
| `/authors` | All authors with stats: posts, likes, dislikes, approval %, average `citationValidRatio`, average latency. |
| `/authors/[slug]` | Author info + stats + their posts. |
| `/about` | Methodology: the pipeline, the active prompt template text, the validation rules. |
| `/login`, `/signup` | Email + password forms. |
| `/me` | Signed-in user's favorites and comments. |

### Admin (role = `admin`, check in `app/admin/layout.tsx`)
| Route | Content |
|---|---|
| `/admin` | Counts + last 20 generation runs + "Run pipeline now" button. |
| `/admin/providers` | List / create / edit / delete. API key field is write-only (never sent to the client). "Test connection" calls `GET {baseUrl}/models`. |
| `/admin/authors` | List / create / edit / enable / disable. Model picker filled from the provider's `/models` result. |
| `/admin/feeds` | List / create / enable / disable, showing `lastFetchedAt` and `lastError`. |
| `/admin/prompts` | List versions, create a new version, set it as active. |
| `/admin/runs` | Paginated runs with status filter; detail view shows `rawOutput` + `error`. |
| `/admin/comments` | Latest comments, hide/unhide. |

### Server actions (`apps/web/src/actions/`)
- `react(postId, value)`: upsert or remove the reaction (same value toggles it off), then
  recompute the post's counts in the same transaction. Requires login.
- `toggleFavorite(postId)`: requires login.
- `addComment(postId, body, parentId?)`: requires login. Body 1–2000 chars. Max depth 2.
  Rate limit: 5 comments per user per minute (simple DB count check).
- `recordShare(postId, channel)`: does not require login.

### Share
Use `navigator.share` when available. Otherwise open a Headless UI `Menu` with: Copy link,
X (`https://x.com/intent/post?url=`), Reddit (`https://www.reddit.com/submit?url=`), Email
(`mailto:?subject=&body=`). Each option calls `recordShare`.

## 7. Security Rules
- Provider API keys are encrypted with AES-256-GCM (`packages/core/src/crypto.ts`),
  stored as `iv:tag:ciphertext` in base64. They are only decrypted in the worker and in the
  admin "Test connection" server action.
- Every admin server action re-checks `role === 'admin'` on the server.
- Comment bodies are rendered as plain text, never HTML.
- Model output is rendered from the validated JSON only, never as raw HTML/markdown.

## 8. Task List

Each task ends with a "Done when" check. Commit after each task.

### Phase 1 — Scaffold
- **T1. Workspace.** Root `package.json`, `pnpm-workspace.yaml`, `tsconfig.base.json`,
  `.gitignore`, `.env.example`. Empty packages with their own `package.json` + `tsconfig.json`.
  *Done when:* `pnpm install` succeeds.
- **T2. Postgres.** `docker-compose.yml` with the `pgvector/pgvector:pg16` image, volume
  `pgdata`, port 5432. *Done when:* `docker compose up -d postgres` works and `psql` connects.
- **T3. Next.js app.** Create `apps/web` (App Router, TS, Tailwind v4, `src/` dir). Add
  `@headlessui/react` and `@heroicons/react`. Basic layout with a header (site name, Authors,
  About, login/user menu). *Done when:* `pnpm --filter @stn/web dev` shows the layout.

### Phase 2 — Database
- **T4. Drizzle setup.** `packages/db`: `client.ts` (exports `db`), `drizzle.config.ts`, the
  first migration runs `CREATE EXTENSION IF NOT EXISTS vector`. *Done when:*
  `pnpm --filter @stn/db migrate` succeeds.
- **T5. Better Auth.** Configure in `apps/web/src/lib/auth.ts` with Drizzle adapter, email
  and password, `admin` plugin. Generate auth tables into the schema. A hook sets
  `role='admin'` when the email equals `ADMIN_EMAIL`. Login/signup pages. *Done when:* you can
  sign up, log in, log out, and the admin email gets the admin role.
- **T6. Content + interaction schema.** All tables from section 3 + migration. *Done when:*
  the migration applies cleanly on an empty database.
- **T7. Seed.** `packages/db/src/seed.ts`: feeds (section 5) + prompt template v1 (active).
  Must be safe to run twice. *Done when:* `pnpm --filter @stn/db seed` run twice gives no
  duplicates.

### Phase 3 — Core library
- **T8. crypto.ts** `encrypt(plain)` / `decrypt(stored)`. *Done when:* a Vitest round-trip
  test passes.
- **T9. article-schema.ts + validate.ts** (section 4). *Done when:* Vitest tests cover
  a valid article, bad JSON, a bad citation number, and copied text.
- **T10. llm.ts** `createClient(provider)` → AI SDK openai-compatible instance;
  `listModels(provider)`; `writeArticle(author, provider, packet, template)` returns
  `{ text, usage, latencyMs }`. `extractJson(text)` strips code fences. *Done when:* the
  `extractJson` unit tests pass.
- **T11. prompt.ts** `renderPrompt(template, packet)`. *Done when:* a unit test checks that
  sources are numbered correctly.

### Phase 4 — Admin
- **T12. Admin layout + guard.** Non-admins get a 404. *Done when:* a normal user cannot open
  `/admin`.
- **T13. Providers CRUD + Test connection.** *Done when:* adding Venice and clicking Test lists
  its models.
- **T14. Authors CRUD.** *Done when:* an author can be created with a model picked from the list.
- **T15. Feeds, Prompts, Runs, Comments pages.** *Done when:* each page lists data and its
  actions work.

### Phase 5 — Worker
- **T16. Worker bootstrap.** `apps/worker/src/index.ts` starts pg-boss, registers queues,
  schedules `pipeline.tick`. *Done when:* the worker starts and logs the scheduled tick.
- **T17. ingest.** *Done when:* running it fills `raw_article` with embeddings.
- **T18. cluster.** *Done when:* related headlines share an `eventId` and events have
  `outletCount`.
- **T19. select + build-packet.** *Done when:* at most `EVENTS_PER_RUN` packets are created,
  and running it again creates no new packets for the same events.
- **T20. generate.** *Done when:* each enabled author produces a `post` or a run with a
  clear `failed`/`invalid` reason.
- **T21. "Run pipeline now".** The admin button sends `pipeline.tick`. *Done when:* clicking it
  produces posts end to end.

### Phase 6 — Public site
- **T22. Home feed** `/`.
- **T23. Event page** `/events/[id]` with author tabs.
- **T24. Post page** `/posts/[slug]` with citations + sources.
- **T25. Authors list + author page** with stats (SQL aggregates).
- **T26. About page** showing the active prompt.
*Done when (all):* pages render from real pipeline data, and empty states look fine.

### Phase 7 — Interactions
- **T27. Reactions** (like/dislike toggle, optimistic UI via `useOptimistic`).
- **T28. Favorites** + `/me` page.
- **T29. Comments** (threaded to depth 2, rate limit, hidden comments not shown).
- **T30. Share menu** + `recordShare`.
- **T31. OG metadata** (`generateMetadata`) + `opengraph-image.tsx` for posts.
*Done when (all):* a logged-out user is sent to `/login` when trying to interact, and counts

### Phase 8 — Deploy
- **T32. Dockerfiles** for `web` (Next.js standalone output) and `worker` (pre-download the
  embedding model at build time into the image). Compose services: `postgres`, `migrate`
  (one-shot), `web`, `worker`.
- **T33. Dokploy.** Compose deployment, env vars, domain + HTTPS, daily `pg_dump` backup.
*Done when:* the public URL serves the site and the cron produces posts every 4 hours.
