# slopthenews — Implementation Plan

A news aggregation site where AI models ("authors") each write their own article about the
same current event from the same frozen set of RSS sources. Readers react, favorite, comment,
and share. Think of it as a public editorial benchmark.

> **How to use this plan:** Work through the tasks in order. Each task lists the files to
> create, what to build, and how to check it is done ("Done when"). Do not start a task until
> the previous one passes its checks. Do not add features that are not listed.

## 4. Article Output Contract (`packages/core/src/article.ts`)

Authors write **Markdown**, not JSON. Models are much better at writing Markdown than at
writing long text inside escaped JSON strings, and Markdown keeps formatting (subheads, lists,
emphasis, tables). That formatting is part of what we are comparing.

### Required response shape
```markdown
# Headline goes here

> One-sentence summary (the "dek").

Opening paragraph with facts and citations [1][3].

## Optional subhead

More paragraphs. Where sources disagree, say so [2][4].
```

Rules given to the model (also shown on `/about`):
1. The first line is the headline as a level-1 heading (`# `).
2. Next comes a single-line blockquote (`> `) with a one-sentence summary.
3. The body uses only: paragraphs, `##` / `###` subheads, bullet or numbered lists, `**bold**`,
   `*italic*`, blockquotes for short attributed quotes, and tables.
4. No links, images, HTML, or code blocks. Sources are cited only with `[n]`.
5. Cite sources by number in square brackets right after the claim: `[1]`. For multiple
   sources use `[1][3]`.

### Source packet payload (what every author receives)
```json
{
  "eventTitle": "…",
  "sources": [
    { "n": 1, "outlet": "BBC", "title": "…", "publishedAt": "…", "url": "…", "text": "… (max 1500 chars)" }
  ]
}
```
At most 8 sources per packet. Take one article per outlet first, then fill with the newest.

### Parsing: `parseArticle(raw: string, packet) → ParsedArticle | { error }`
Steps, in this order:
1. **Normalize.** Trim. If the whole response is wrapped in a code fence (```` ``` ```` or
   ```` ```markdown ````), unwrap it. Remove `<think>…</think>` blocks (some reasoning
   models emit these). Drop every line before the first line that starts with `# `.
2. **Normalize citations** with plain string replacement (not the Markdown parser):
   `[1, 3]` / `[1,3]` → `[1][3]`; `[^1]` → `[1]`; `【1】` → `[1]`.
3. **Split.** Headline = text of the first H1 line. Dek = the first blockquote line right
   after it (strip the `> `). Body = everything after the dek.
4. **Check citations.** Find every `\[(\d+)\]` in the body. A number is valid when
   1 ≤ n ≤ number of sources in the packet. Remove invalid markers from the body string.
5. **Analyze** the body with `fromMarkdown(body, { extensions: [gfm()], mdastExtensions: [gfmFromMarkdown()] })`:
   - `wordCount` = word count of `toString(tree)`.
   - `paragraphCitationRatio` = paragraphs (and list items) containing at least one `[n]` /
     all paragraphs (and list items).
   - Collect the plain text of each paragraph for the copy check.

`ParsedArticle` = `{ headline, dek, bodyMarkdown, wordCount, citations: number[] (unique, sorted),
citationValidRatio, paragraphCitationRatio }`.

The body is stored **as Markdown text** (`post.bodyMarkdown`). It is never re-serialized
(re-serializing can escape `[1]` into `\[1]`). Unsafe elements are removed at render time
(section 7).

### Validation rules (`packages/core/src/validate.ts`)
The run is `invalid` (with a clear `error` message) if any rule fails:
1. There is no H1 headline, or the headline is not 10–140 characters long.
2. There is no dek, or the dek is not 20–300 characters long.
3. `wordCount` is under 150 or over 1500.
4. Fewer than 50% of citation markers are valid, or there are no valid citations.
5. `paragraphCitationRatio` is under 0.5.
6. Any paragraph contains 30 or more consecutive words copied from one source's text.
   Compare lowercased words with punctuation removed.

`citationValidRatio` = valid markers / all markers (before invalid ones are removed).

## 5. Pipeline (apps/worker)

pg-boss queues and the order they run in:

```
pipeline.tick (cron PIPELINE_CRON)
  └─> ingest  ──> cluster ──> select ──> for each selected event: build-packet
                                                  └─> for each enabled author: generate
```

| Job | Input | Does | Output |
|---|---|---|---|
| `pipeline.tick` | — | Sends `ingest`. Exits early if no enabled author exists. | — |
| `ingest` | — | For each enabled feed: parse RSS, insert new `raw_article` rows (skip URLs already stored), try to fetch the page + Readability for `content` (5s timeout, failures are ok), compute embedding of `title + excerpt`. Then send `cluster`. | rows |
| `cluster` | — | For each `raw_article` with `eventId IS NULL`: find nearest `event` with `lastSeenAt` within `CLUSTER_WINDOW_HOURS` and cosine similarity ≥ `CLUSTER_SIMILARITY`. If found: attach, update centroid (running mean), `lastSeenAt`, `outletCount` (distinct outlets). Else: create event with `title = article.title`. Then send `select`. | events |
| `select` | — | Pick events with `status='open'`, `outletCount ≥ MIN_OUTLETS_PER_EVENT`, ordered by `outletCount DESC, lastSeenAt DESC`, limit `EVENTS_PER_RUN`. Set `status='queued'`, send `build-packet` for each. | — |
| `build-packet` | `{eventId}` | Create `source_packet` (skip if exists — **this is the de-dupe**). For each enabled author, insert `generation_run` (pending) and send `generate`. Set event `status='generated'`. | runs |
| `generate` | `{runId}` | Load author + decrypt provider key. Call model via AI SDK `generateText` with the active prompt template. Run `parseArticle` + validate on the response text. On success: insert `post` + `post_citation`, `status='succeeded'`. Record latency and tokens either way. Retry limit 2 for network errors only. | post |

Concurrency: `generate` uses `teamSize: 2`. Each job is idempotent: check state before acting.

Note: plain `generateText` returning Markdown works with every OpenAI-compatible endpoint.
No JSON mode or structured-output support is needed.

### Prompt template v1 (seeded, `packages/db/src/seed.ts`)
Placeholders: `{{eventTitle}}`, `{{sourceCount}}`, `{{sources}}`.

**System:**
```
You are a news writer for a news site. Write one neutral, factual news article that combines
the provided sources into a single story.

Rules:
- Use only facts found in the sources. Do not add outside knowledge.
- Cite sources by number in square brackets right after each claim, like [1] or [2][3].
  Only use numbers from 1 to {{sourceCount}}.
- Every paragraph must have at least one citation.
- Where sources disagree, say so and cite each side.
- Do not copy sentences from the sources. Short quotes are allowed if attributed.
- Length: 300 to 800 words.

Format your answer as Markdown, exactly like this:
# Headline

> One-sentence summary.

Body paragraphs. You may use ## subheads, lists, **bold**, *italic*, and tables.
Do not use links, images, HTML, or code blocks.

Reply with the article only.
```

**User:**
```
Event: {{eventTitle}}

Sources:
{{sources}}
```
Each source in `{{sources}}` is rendered as:
```
[n] Outlet — Title (publishedAt ISO date)
text
```
with a blank line between sources.

## 7. Design System (apps/web)

The look is a calm, newspaper-like reading page. Keep chrome minimal. Use hairline rules
instead of shadows. Use serif type for reading, sans for UI, and mono for model data.

### Fonts (`apps/web/src/app/fonts.ts`)
| Role | Font | Used for |
|---|---|---|
| Serif (`--font-serif`) | **Newsreader**, variable, with optical sizing (`axes: ['opsz']`) | Headlines, deks, article body |
| Sans (`--font-sans`) | **Inter**, variable | Navigation, buttons, forms, admin, metadata |
| Mono (`--font-mono`) | **JetBrains Mono** | Model IDs, stats (latency, tokens, ratios) |

Load all three with `next/font/google` (`display: 'swap'`, `subsets: ['latin']`) and put
their `.variable` class names on `<html>`. Newsreader was designed for on-screen news reading.
If it looks too narrow, use Source Serif 4 instead (only this file changes).

### Type scale
- Article body: `prose prose-lg font-serif`, line height 1.7, max width `68ch`.
- Post headline: `font-serif font-semibold text-4xl md:text-5xl tracking-tight leading-tight`.
- Dek: `font-serif italic text-xl text-muted`.
- Metadata line (author · date · read time): `font-sans text-sm text-muted`.
- Stats: `font-mono text-xs tabular-nums`.

### Color tokens (`apps/web/src/app/globals.css`)
Define these as CSS variables and map them in Tailwind's `@theme` (`--color-paper`, and so on)
so classes like `bg-paper text-ink border-rule` work.

| Token | Light | Dark | Use |
|---|---|---|---|
| `paper` | `#FAF8F3` | `#141311` | Page background |
| `surface` | `#FFFFFF` | `#1C1B19` | Cards, menus, inputs |
| `ink` | `#1C1B19` | `#ECE8E1` | Main text |
| `muted` | `#6B6760` | `#A29D94` | Secondary text |
| `rule` | `#E4E0D8` | `#2E2C28` | Borders, dividers |
| `accent` | `#B4232A` | `#F0626A` | Links, active tab, focus ring, "AI-generated" label |

Every text color meets WCAG AA contrast on `paper` in both modes.

### Light / dark mode
- Wrap the app in `next-themes` `ThemeProvider` with `attribute="class"`,
  `defaultTheme="system"`, `enableSystem`, `disableTransitionOnChange`. Add
  `suppressHydrationWarning` to `<html>`.
- In `globals.css`: `@custom-variant dark (&:where(.dark, .dark *));`, and set the dark token
  values under `.dark { … }`.
- Theme switcher in the header: a Headless UI `Menu` with three items, System / Light / Dark,
  using heroicons `ComputerDesktopIcon` / `SunIcon` / `MoonIcon`. Render it only after mount
  to avoid a hydration mismatch.
- Article prose: `prose dark:prose-invert`, with the typography plugin colors set to the tokens.

### Markdown rendering (`apps/web/src/components/ArticleBody.tsx`)
- `react-markdown` with `remarkPlugins={[remarkGfm, remarkCitations]}` and `skipHtml`.
- `allowedElements`: `p, h2, h3, ul, ol, li, strong, em, blockquote, table, thead, tbody, tr, th, td, hr, sup, del`.
  Use `unwrapDisallowed` so that links, images, and anything else become plain text.
- Custom components: `h1` renders as `h2` (just in case), `table` is wrapped in a
  horizontally scrollable `div`.
- `remarkCitations` (`apps/web/src/lib/remark-citations.ts`): a small plugin that walks text
  nodes and replaces each `[n]` with a `sup` element node. Its `data.hName = 'sup'`, and its
  child is the text `n`. Give it a Vitest test.
- The `sup` component renders `<CitationRef n={n} />`: a Headless UI `Popover` that shows
  the outlet, source title, and an external link. It links to `#source-n` in the source list.

### Page patterns
- **Masthead:** wordmark "slopthenews" in Newsreader bold, today's date in small caps sans,
  a thin double rule underneath. Navigation on the right: Authors, About, theme switcher,
  user menu.
- **Home:** the first event is the "lead" (large serif headline, full width). The rest are a
  list separated by rules. Each event shows the event title, the source outlet names, and one
  **author chip** per post: a colored dot (`author.color`) plus the display name. The chip
  links to that post.
- **Post page:** a small "AI-generated · {model id in mono}" label in `accent` above the
  headline, then headline, dek, metadata line, body, numbered "Sources" list (`id="source-n"`),
  action bar (like, dislike, favorite, share as heroicon buttons with counts), and comments.
- **Event page:** headline and outlet list, then Headless UI `TabGroup`. Each tab label is
  an author chip; each panel is that author's post plus a stats strip (words, latency,
  tokens, citation ratio).
- **Admin:** plain sans UI with tables and forms, the same tokens, and no serif.
- **Responsive:** mobile-first single column; the home lead plus list becomes two columns at `lg`.
- **Accessibility:** semantic `<article>`, `<header>`, `<time dateTime>`; visible
  `focus-visible:ring-2 ring-accent`; respect `prefers-reduced-motion`; icon buttons have
  `aria-label`s.

## 8. Security Rules
- Provider API keys are encrypted with AES-256-GCM (`packages/core/src/crypto.ts`),
  stored as `iv:tag:ciphertext` in base64. They are only decrypted in the worker and in the
  admin "Test connection" server action.
- Every admin server action re-checks `role === 'admin'` on the server.
- Comment bodies are rendered as plain text, never HTML.
- Model Markdown is rendered only through `ArticleBody` (`skipHtml` + `allowedElements`).
  Raw HTML from a model is never rendered, and model output never contains clickable links;
  the only links are to sources from our own database.
